# 대형 화면 선명도·화면 맞춤 — 로컬 검증

## 변경 이유와 파일

- js/audio.js는 기존 배포 버전으로 복원했다. 직전에 추가한 음악 루프/징글 파일과 재생 경로를 제거하고 기존 자체 합성 효과음은 유지한다. 부드러운 선두권 카메라 개선은 유지한다.
- js/themes.js의 renderDensity는 실제 CSS 크기와 DPR로 표시 해상도를 계산한다. DPR 최대4, 캔버스당 12MP 예산을 둔다. 4K CSS 화면/DPR1, 1920×1080/DPR2, 960×540/DPR4는 원래 출력 픽셀을 유지한다. 저품질 모드도 맵/공의 표시 해상도를 낮추지 않는다. 경기 물리 상수는 변경하지 않는다.
- js/renderer.js의 배경·비네트, 맵 장식 타일, 장애물 이미지, 미니맵을 표시 밀도로 생성한다. 맵 타일은 현재 최고 밀도 하나를 재사용하고 장애물 이미지는 4단계 크기를 캐시한다. 확대·화면 이동에 따른 DPR 변경도 감지한다.
- js/cinematic.js는 동일한 표시 해상도 계산을 적용한다.
- js/main.js는 30Hz 표시를 품질 저하로 오판하지 않는다. 22fps 미만이 6초 이상이면 일시적으로 효과량만 줄이고 사용자의 품질 설정을 저장/덮어쓰지 않는다.
- style.css는 데스크톱 옆 메뉴를 현재 화면 높이에 제한한다. 짧은 화면에서 정보/미니맵을 줄이고 순위 영역을 스크롤하며, 카메라 버튼은 화면 안에 남긴다. 설정 패널의 머리글/시작 버튼이 스크롤 내용에 밀리지 않도록 한다.
- js/ui.js는 데스크톱 경기 표시 영역에 고정 최소 높이200을 강제하지 않는다. 현재 가용 높이를 사용한다.

## 기본 검증

`node --test qa/tv-display.test.cjs qa/camera-motion.test.cjs tests/visual-renderer.test.cjs tests/camera.test.cjs tests/ui-launch.test.cjs qa/audio-muted.test.cjs`: 26개 통과, 실패0. 해상도/12MP 예산/효과 모드별 선명도 유지/캐시/음악 제거와 기존 카메라·UI·효과음 검사. 전체 QA/대량 공정성 측정은 요청에 따라 실행하지 않았다.

`node qa/tv-display/browser.cjs`: 로컬 /moonbangoo_PinBall/에서 기본 6공 마우스 경기 하나와 직전 게임 정확한 재현. 1280×720/DPR3(실제3840×2160), 960×540/DPR4(브라우저 확대에 대응), 640×360/DPR3 세 가지 배치만 확인한다. 설정 시작 버튼, 경기 영역, 추적/보기 버튼의 화면 내 배치, 가로 넘침 없음, 배경과 캔버스 해상도 일치, 콘솔/네트워크 오류0을 검사한다. 낮은 화면 갱신 조건에서도 사용자 high 설정은 유지된다. 원시 결과·캡처는 results/.

경기 맵·물리·셔플·참가자 배정·재현·당첨 계산 파일은 이전 배포 커밋과 diff가 없다. 이번 그래픽 변경 후 공정성 합격을 새로 주장하지 않는다.

## 한계

실제 TV는 접근할 수 없어 Chrome의 CSS 화면 크기/DPR로 재현했다. TV 패널 자체의 해상도, 영상 보정/오버스캔, OS 배율, 터치 드라이버는 실기기 확인이 필요하다. 최대12MP를 넘는 초고해상도에서는 메모리/렌더링 비용을 제한하려고 해상도가 낮아질 수 있다. 이번에는 대량 공·모든 기기 조합·터치 완주 검사를 반복하지 않았다. 배포 후에는 공개 파일이 검증한 커밋과 일치하는지 별도로 확인한다.
