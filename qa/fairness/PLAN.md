실행 자원 기록: 후보a/b와 추가 확인의 동시 실행에서 CPU 경합이 발생해, 후보a/b 계산 프로세스를 일시 대기한 뒤 확인을 우선 실행하고 재개한다. 입력의 `now`는 고정 tick 기반 합성 시간이라 운영체제의 계산 대기가 경기·손 프로토콜을 바꾸지 않는다. 보고서의 표본 `cpuMs`/단계 wall time은 대기까지 포함한 경과 시간으로, 제품의 FPS/CPU 벤치마크로 사용하지 않는다.

수치 경계 회귀(holdout 실행 전): 편차를 관측율−기대율의 부동소수점 뺄셈 대신 `abs(우승수−기대수)/N×100`으로 계산한다. N3,000의1,545/1,455는 정확1.5pp라 합격선의 ≤를 만족한다. 1,546/1,454는1.533pp라 불합격이다. p≥0.01 및1.5pp 기준은 그대로다. 진행 중 dev 작업의 원시 gzip은 유지하고, 표와 판정은 횟수에서 이 계산으로 다시 산출한다.
