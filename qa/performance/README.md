# 고해상도 성능 최적화

## 수정 파일과 이유

- index.html, style.css: 고정 종이 질감/비네트를 game-surface에 표시한다. 경기 중 불투명 HUD에서는 실시간 backdrop blur를 제거한다. UI/물리 영역과 입력은 그대로다.
- js/renderer.js: 전체 화면의 종이/비네트는 크기·테마가 바뀔 때만 합성한다. 프레임마다 두 번 그리던 전체 화면 효과를 없앴다. 합성 후 임시 비네트 텍스처를 해제하며 같은 크기의 resize는 버퍼를 재생성하지 않는다. 기본 해상도는 기존과 같고, 부하 대응은 동적 캔버스의 픽셀 수만 조절한다.
- js/display-budget.js: 실제 표시 간격에서 반복 지연을 감지하는 표시 전용 예산. 90프레임의 하위10% 간격을 정상 주기로 삼아 native30Hz를 저성능으로 오판하지 않는다. 지연 비중18% 초과 또는 지속 주기23.5fps 미만 시 해상도 배율을85%로 줄이며 최저65%. 여유가6개 구간 유지되면8%씩 회복한다. 일회성 멈춤·숨김 탭/해상도 전환의 오래된 간격은 제외한다. 고정 FPS나 모든 하드웨어의60fps를 보장하지 않는다.
- js/main.js: 표시 예산을 사용하며 경기 계산의 STEP/accumulator/speed/seed는 변경하지 않는다. 패널 전환 중에는 매 프레임 위치를 읽고 안정적인 경기 중에는 HUD 갱신 주기에 맞춘다.
- js/cinematic.js: 준비/비행 캔버스도 같은 표시 배율을 따른다. CSS 좌표·출발 상태·비행 목표는 그대로다.
- js/ui.js: 같은 시간/공 수/이름/색의 DOM을 반복 교체하지 않고 필요한 내용만 갱신한다. 새 게임에서 같은 ID가 다른 그룹/이름을 가지는 경우도 반영한다.

## 기본 전후 측정

`node qa/performance/browser.cjs before|after` — 동일 Chrome/컴퓨터, 기본6공, 데스크톱1920×1080/DPR1 및 TV3840×2160/DPR1+CPU2배 부하, 각5초 표본. 이 환경에서는 최적화 전에도 약60fps였으므로 실제 TV의 렉을 재현하거나 기기별 개선율을 보장하는 측정은 아니다. JS에서 관찰한 렌더 명령 시간이며 GPU 실행 전체 시간은 아니다.

| 조건 | 평균 렌더(ms) 전→후 | p95 렌더(ms) 전→후 | p95 프레임 간격(ms) 전→후 | 위치 조회 전→후 |
|---|---|---|---|---|
| 데스크톱 |0.524→0.458|0.800→0.700|16.7→16.7|302→106|
| 4K + CPU2배 |0.776→0.568|1.100→0.900|16.8→16.7|302→107|

4K 평균 렌더 작업 약27%, 위치 조회 약65% 감소. 부하가 낮았던 측정 환경에서는 전체 FPS 증가를 주장하지 않는다. 후측정 이후의 순위 행 재사용 보완/임시 텍스처 해제/화면 변경 시 측정 초기화는 아래 기본 검사로 확인한다.

## 검증

관련 회귀25개: 표시 예산/30·60·120Hz/해상도 재생성 방지/배경 안정성/기존 UI·표시·재현. results/combined-unit.txt.

before.json/after.json: 기본 두 경기 모두6개 완주, 완주 순서/시간의 재현 일치, 요청/페이지 오류0. 프레임 지연이 없어서 native4K를 유지한다.

`node qa/performance/adaptive-browser.cjs`: 최저 배율을 강제한 확대 화면(960×540/DPR4)에서 합성 터치6공 완주·출발 기록/완주 순서/시간 재현 일치, 오류0. 동적 캔버스2496×1404, 고정 재질3840×2160, HUD blur:none. 그룹명이 바뀌어도 재사용 순위 행이 올바르게 갱신된다. 강제 배율 검사는 실제 TV 성능 측정이 아니다. 정상 정책은 반복 프레임 지연을 보고 자동 조절한다. results/adaptive-touch.json 및 캡처.

## 한계

실제 TV GPU·브라우저·디스플레이는 직접 접근하지 못했다. 사용자가 동일 TV에서 확인해야 한다. 모든 하드웨어/500공/브라우저 조합이나 전체 QA·공정성 대량 측정은 이번에 실행하지 않았다. 경기 물리/맵/스킬/셔플/출발·재현 파일은 이전 배포와 diff가 없다. 경기 결과를 바꾸거나 물리 스텝을 버려 FPS를 높이는 방식은 사용하지 않는다. 성능에 따라 동적 공/맵 가장자리가 조금 부드러워질 수 있으며 고정 UI/재질은 native 해상도다.
