# TV 크롬 검토·맵 상단 무작위 출발 — 검증 기록

실제 TV 장비는 접근할 수 없어 Chrome에서 원본 4K(3840×2160/DPR1)와 확대된 화면(960×540/DPR4)을 실행했다. 두 환경의 공개 사이트에서 실제 터치 입력으로 설정→기울이기→셔플→발사→경기까지 확인했다. 원시 출발 좌표·시드·캡처는 results/public-before.json과 before-*.png에 저장했다. 콘솔/요청 오류는 없었고 6공 출발 폭은 70.76/71.92, 평균 X는 700.74/719.91이었다. 맵 중심 X는500이다.

## 원인·변경

기존 commitHandStart는 손의 출구 방향으로 이동한 셔플 덩어리의 중심을 그대로 spawn으로 투영해, 오른쪽 출구에서 뭉쳐 던질수록 오른쪽에 뭉쳐 도착했다.

js/hand-start.js가 별도 `seed|top-scatter-v2` RNG로 출발점을 생성한다. 50개 이하에서는 맵 상단의 수평 구간별 무작위 위치를 사용해 작은 그룹도 좌우로 퍼지도록 한다. 많은 공은 장애물이 없는 기존 spawn 안의 충돌 없는 위치를 사용한다. Fisher–Yates로 참가자/색과 무관하게 슬롯을 배정하며 던지는 방향의 우측 속도를 경기 시작에 인계하지 않는다. 경기 RNG·맵·경기 물리 상수·셔플 계산·스킬 확률·당첨 규칙은 바꾸지 않는다. 실제 시작 위치/속도를 바꾸는 출발 프로토콜 수정이다.

비행은 이미 확정한 각 공의 출발점에 도착한다. 색/ID를 교체하지 않고, 기존 비행의 위치/반경/속도 연속성 검사를 유지한다. 재현 signature와 record.version을 v2로 올렸다. v1 기록은 물리 상태를 변경하기 전에 안전하게 거부한다. 새 게임을 섞어 새 기록을 만들어야 한다.

TV 원본 4K에서는 기존 줌 상한 때문에 맵이 지나치게 좁았다. js/camera.js가 가용 폭2000 이상에서 표시 줌 상한2.4를 사용한다. style.css는 순위 패널이 내용 없이 세로로 길게 늘어나지 않도록 하되 짧은 화면에서는 계속 스크롤하도록 한다. 표시 수정은 물리 상태를 변경하지 않는다.

## 기본 검사

- 관련 재현·산포·비행·카메라 회귀26개 통과: results/unit.txt.
- 기존 손 출발 회귀의 요구사항을 새 프로토콜에 맞춰 수정했다. 위치·접촉·RNG·입력 검증5개 통과: results/packing-tests.txt. 손을 움직여 고정 시드의 우승을 바꾸어야 한다는 구버전 요구는 철회했다.
- `node qa/top-scatter/browser.cjs`: 로컬 4K 마우스와 확대된 화면의 터치, 기본6공 각각 완주. 출발 기록/완주 순서/완주 시간이 정확히 재현되며 콘솔·네트워크 오류0. 산포/평균 X와 캡처는 results/local-after.json, after-*.png. 전후 공개 브라우저 경기는 서로 다른 시드의 관찰이며 통계적 우승 공정성 비교가 아니다.
- `node qa/top-scatter/compare.cjs`: 동일 시드·동일 우측 셔플 입력을 이전 배포 코드와 현재 코드에 넣은 통제 비교. results/controlled-comparison.json. 동일 입력에서 평균 X685.12→476.83, 출발 폭46.72→770.84로 바뀌었다.

## 미검증

최종 우승 ID/그룹의 holdout 공정성 측정은 미완료다. 슬롯 무작위 배정과 경기 RNG 무변경 검사만으로 우승 확률 합격을 주장하지 않는다. 기존 qa/fairness/PLAN.md의 최종 합격선은 변경하지 않았다. 실기기 TV의 터치 드라이버, 오버스캔, OS 배율은 별도 확인이 필요하다. 전체 QA/대규모 경기 측정은 실행하지 않았다. 배포 후에는 공개 파일이 검증한 커밋과 일치하는지 별도로 확인한다.
