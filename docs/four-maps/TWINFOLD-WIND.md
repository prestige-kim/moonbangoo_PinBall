# 갈래 서가 — 2초 주기 상승 바람

사용자 요청으로 결승 구간의 회전 책갈피6개를 제거하고 y9020/y10760의 상승 바람2곳으로 교체했다. 기존 좌우 책 수레2개와 반납 선반1개는 유지했다. 지형 버전은6에서7로 올렸다.

## 동작과 화면

- 기본 속도 기준2초마다0.4초 분출, 나머지1.6초는 대기한다. 물리 시간으로 계산하므로 일시정지 시 주기도 멈추며 속도 설정에 따라 게임 전체와 함께 빨라지거나 느려진다.
- 분출 중 바람길(너비600·높이300) 안에서 낙하하던 공을 위로 띄우고, 바람길 중심을 기준으로 양쪽으로 퍼뜨린다. 중력에 맞춰 초기 상승 속도를 계산해 약180단위 높이의 상승 궤적을 만든다. 이후 중력으로 다시 낙하한다. 공을 순간이동하거나 순위를 조작하지 않는다.
- 한 공에 같은 분출을 여러 번 적용하지 않는다. 이미 띄워진 공은3초간 같은 송풍구의 재영향을 받지 않아 바로 다음 분출에 붙잡히는 것을 막고, 다음 주기의 다른 공들은 정상적으로 띄운다. 이 동작은 모든 공에 똑같이 적용하며 참가자ID나 난수를 사용하지 않는다.
- 송풍구·바람 범위의 색 면·상승하며 바깥으로 휘는 바람 선·위쪽 화살표를 그린다. 분출 시 선과 색이 강해지고 대기 시에는 연한 정적 안내선과 다음 주기를 표시하는 원형 표시만 남는다. 물리와 그림은 같은 시간 함수로 동기화한다. 화면 효과 줄이기 설정에서는 선의 이동을 줄여도 물리 동작은 유지한다.
- 바람은 무형 필드다. 슬롯으로 그려진 송풍구는 고체 발판이 아니며 닫힌 벽을 만들지 않는다. 이번 요청은 종전의 '충돌만으로 진행'하던 갈래 서가에 명시적으로 보이는 힘을 추가하는 변경이다. 기존 랜덤 스킬과 숨겨진 막힘 방지는 계속 사용하지 않는다.

## 검증

- 최종 코드 `npm test`: **268개 통과**, 실패0개. `/tmp/twinfold-wind-final-tests.log`.
- 바람 전용 검사3개:2초 분출/대기 경계, 같은 분출 중 중복 적용 방지, 다음 주기의 다른 공 상승, 실제 위쪽 이동→양쪽 분산→중력 낙하→완주, 분출/대기 화면의 차이를 확인했다. 부동소수점 때문에2.4초가 분출로 판정되는 초기 경계 문제를 수정한 뒤 최종 코드 전체 검사를 다시 실행했다.
- `node qa/four-maps/run-map.cjs twinfold`: 설정 조합108개 및 실제 출발18개 정확 재현, 실패0개. 공1/2/6/25/49/50, 반지름8/16·중력350/1500·반발력0.35/0.92 조합 포함.240초 상한 내 모두 완주했다.
- `node qa/four-maps/twinfold-pace.cjs`: 새로운 `library-pace-wind-v7-` 시드로60쌍120경기. 동일 출발 배열·설정으로 비교한 완주 중앙값은 다음과 같다. 단위는1배속 환산 물리 시간이다.

공통 물리 코드에 바람 타입의 처리 분기가 필요했으므로, 이전 로컬 커밋2a14240의 JS를 별도 `/tmp/pinball-before-wind-2a14240`에 추출해 바람이 없는 세 맵을 비교했다. 기본 맵/빗살 낙하/박자 분배기 각각 공6/50×B/C/D 실제 출발로18쌍을 실행했고 **모든 참가자의 순위와 완주 시간이 정확히 일치**했다. 사용한 검사는 `qa/four-maps/wind-parity.cjs`이며 이전 소스는 `QA_SOURCE_ROOT`로 선택한다. 오디오·셔플·입력·카메라·당첨 규칙 소스는 이번에 변경하지 않았다.
