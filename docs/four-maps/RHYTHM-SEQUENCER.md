# 박자 분배기 v3 — 교대·엇박·연쇄

2026-10-14. 요청 범위는 추천한 교대 셔터, 엇박 회전 패들, 연쇄 게이트 조합의 구현과 로컬 검증이다. 시작 후보는 `1f54780b4c56d9bce814d0b3ff877ce6ad56b703`, 분기는 `codex/four-maps-local`이다.

## 구현

- 상단 교대 셔터 4개: 두 쌍의 좌우 셔터가 4.8초 주기로 번갈아 전개·회수된다. 긴 경사면에 공이 닿는 시점과 열린 시점에 따라 통과 간격이 갈라진다.
- 중단 엇박 패들 6개: 세 높이에 좌우 한 쌍씩 배치했다. 반대 방향, 90도 초기 위상 차이, 3.2초 회전 주기로 경로와 도착 순서를 흔든다.
- 하단 연쇄 게이트 4개: 7900/8500/9100/9700 높이에서 0.8초 시차로 전개되며 3.2초마다 반복한다. 완전히 벽 밖으로 회수되는 시간과 항상 열려 있는 우회 폭을 둬 공을 압착하지 않는다.
- 고정 경사로 6쌍은 각각 전체 폭의 수직선을 차단한다. 중간·결승 쪽까지 핀 15개를 배치했다. 총 41개 충돌체이며, 기존의 짧은 막대·핀 배치를 새 흐름에 맞춰 교체했다.
- 배경은 4단계 시퀀서 패턴, 장애물은 청색/청록 기계 장치로 구성했다. 순서 표시등·통과/전환/분할 표시·회전 궤적은 실제 물리 위치와 시각으로 그린다. 별도 음원을 추가하지 않았다.
- 물리 엔진과 힘 적용 코드는 수정하지 않았다. 기존 moving/rotor/segment/pin을 사용하며 공의 ID·그룹·순위를 보고 개입하지 않는다. 셔터는 공을 정확히 한 개씩 배출하는 장치가 아니며 자연 충돌로 간격을 나눈다.

## 호환성과 변경 범위

`rhythm`의 지형 버전을 2 → 3으로 올렸다. v2 출발 기록을 새 지형에서 재생하지 않으며, v3 출발 기록의 정확 재현을 확인한다. 운영 변경은 `js/maps/rhythm.js`, `js/maps/rhythm-style.js`, `js/renderer.js`의 rhythm 전용 분기 및 `index.html`의 세 스크립트 캐시 키다.

테스트의 예전 ‘마지막 20%에 동적 장애물이 없음’ 및 단순 14개 막대 조건은 이번에 승인받은 하단 게이트·세 장치 구조와 맞지 않아 교체했다. 간격 기준 96은 유지하고 4.8/3.2초의 최소공배수인 9.6초 전체를 검사한다. 공 완주·벽 이탈·중첩·구제 금지·재현 기준은 낮추지 않았다. 공용 QA의 간격 검사 함수는 기본 8초를 유지하면서 검사 시간 인자를 추가했다.

## 검증

수치와 최종 소스 해시는 [summary.json](rhythm-sequencer/summary.json)에 기록한다. 원시 행은 `qa/four-maps/results/rhythm-sequencer/` 및 `qa/four-maps/results/rhythm.json`에 남긴다.

- `npm test`: 전체 회귀 검사.
- `node qa/four-maps/run-map.cjs rhythm`: 공 1/2/6/25/49/50개, 반지름 8/16·중력 350/1500·반발력 .35/.92의 극단 조합 및 기본값 108건, 출발 B/C/D 정확 재현 18건, 50개 성능 5건.
- `node qa/four-maps/rhythm-sequencer.cjs positions`: 기본 반지름의 모든 정수 x와 24개 위상, 극단 반지름·양벽·네 중간 진입 높이의 접촉 검사.
- `... full`: 반지름 8/16, 양벽 포함 30개 x, 네 위상에서 전체 코스 240건 완주 검사.
- `... groups`: 실제 출발 B/C/D 각 12시드, 50개 경기 36회. 모든 공의 지형 접촉, 우승자의 실제 리듬 장치 접촉, 세 장치 모두의 접촉 이벤트 확인.
- `... rotors`: 기본값과 8개 극단 설정의 50개 경기에서 매 틱 회전 패들 중첩 깊이·벽 이탈·유한값·완주 검사. 기존 행렬의 segment/moving/pin 중첩 검사에 추가한다.
- 리듬 단위 검사는 같은 위치·속도의 공을 장치별 16개 위상에서 떨어뜨린다. 세 장치 모두 열린 통과와 실제 접촉을 만들며 도착 시간 차이가 0.5초를 넘는다. 그림만 바꾸어 리듬을 주장하지 않는다.
- 데스크톱 브라우저에서 기본 속도로 50개 붓기·발사·진행·결과를 확인했다. [진행 화면](rhythm-sequencer/race50.png), [완주 화면](rhythm-sequencer/result50.png), [장치 미리보기](rhythm-sequencer/preview.html), [미리보기 캡처](rhythm-sequencer/preview.png).

## 기존 기능 보존과 배포 상태

원격 기본 브랜치는 새로 조회·fetch한 main이다. 실제 배포 운영 파일 26개를 `5d25319ddd2d352cf35e314da27329c97daec397`과 대조한 [기록](rhythm-sequencer/deployment.json)을 남겼다. 이 SHA가 후보 이력에 포함됨을 확인했다. Pages 작업 API의 실행 기록을 이번에 새로 조회하지는 않았으며 파일 일치 증거와 구분한다.

시작 후보 대비 운영 파일 54개는 [동일 해시](rhythm-sequencer/preservation.json)다. 기본/갈래 서가/빗살 낙하 지형, 물리 엔진, 음원/MP3/크레딧, 원형 셔플·붓기·발사, 카메라, UI는 그대로다. 변경한 렌더러는 [이전 후보와의 30개 그리기 명령 비교](rhythm-sequencer/render-preservation.json)에서 다른 세 맵의 장애물·배경 출력이 동일했다. 이 비교의 명령은 `node qa/four-maps/rhythm-preservation.cjs`다. 비교 어댑터는 Canvas gradient의 함수 객체를 종류·좌표·색상 명령으로 정규화해 객체 참조 차이를 그림 차이로 오인하지 않도록 했다.

다른 작업의 수정 파일 `qa/fairness/freeze.cjs`, 미추적 `AGENTS.md`, `docs/RELEASE_MANAGEMENT.md`, fairness confirm 결과는 보존한다. 특히 다른 작업의 미커밋 배포 문서를 변경하지 않기 위해 이 문서에 작업 상태를 별도로 남긴다. 전체 회귀 검사는 기존 셔플·음원·추첨 4종·50개 제한·정지·결과·재현·맵/미니맵·기존 바람을 포함한다. 모바일 실기기·실제 스피커 청취·모든 연속 좌표와 위상의 완전 증명은 이번 검증 범위에 포함하지 않는다.

사용자 허가는 로컬 개발 범위다. push·PR·main 병합·배포는 수행하지 않는다. 최종 후보 SHA는 이 기록을 포함하는 로컬 커밋이다.

- 종료 전 원격 main 재조회도 `5d25319ddd2d352cf35e314da27329c97daec397`로 동일했다.
- **로컬 검증 완료**. 이 문서를 포함하는 후보 커밋만 생성하며 원격 반영·배포는 하지 않았다.
