# 빗살 낙하 v5 — 빗살 증설과 빠른 개폐

2026-10-14 작업. 시작 후보 `2e20e821034f1de26d3c0bdbcaf81160a48285ee`, 배포/원격 기준 `5d25319ddd2d352cf35e314da27329c97daec397`.
이 기록은 다른 작업의 미커밋 `docs/RELEASE_MANAGEMENT.md`를 수정하지 않는 별도 상태 기록이다.

## 요청과 변경

- 양쪽 대각 빗살을 3쌍에서 6쌍으로 증설. 중심 높이 1700, 3250, 4800, 6350, 7900, 9450에 배치한다.
- 각 쌍의 왕복 주기 6초 → 4초. 같은 이동 거리를 1.5배 빠르게 이동한다. 게임 속도 1배 기준이며 일시정지 때는 물리 시계와 함께 멈춘다.
- 여섯 쌍의 위상을 균등 분산해 맵 어딘가에서 약 0.667초 간격으로 다음 쌍이 최대 전개된다. 이전 세 쌍은 2초 간격이었다.
- 빗살마다 21개의 촘촘한 이빨, 아래쪽을 향한 치형, 벽 밖 완전 회수, 엇갈린 양쪽 끝의 간격을 유지한다. 공을 강제로 이동시키는 구제 장치를 추가하지 않았다.
- 기존 짧은 발판·핀의 위치를 그대로 두면 증설 장치와 충돌한다. 각 쌍 다음에 전체 폭의 수직 낙하선을 가로막는 엇갈린 경사로를 배치하고 경사로 사이에 핀을 둔다. 진입 경사로 포함 고정 경사로 7쌍, 동적 빗살 12몸체/252개 이빨, 핀 15개: 실제 충돌 부품 293개.
- `cascade`만 v4 → v5. 이전 지형의 출발 기록과 혼용하지 않으며 현재 버전 기록의 정확 재현을 검증한다. `index.html`은 해당 맵 스크립트의 캐시 키만 갱신한다.

## 발견 후 보완한 실패

첫 시안에서 고정 경사로를 상단 한 쌍만 남겼을 때, `x=956, y=6100, radius=8, phase=0`의 중간 진입 공이 모든 하단 장애물을 피했다. 이를 통과로 처리하지 않았다. 각 동적 구간 아래에 고정 경사로 쌍을 추가한 뒤 같은 좌표의 공이 8회 장애물 접촉 후 14.9초에 완주함을 확인했다. 최종 시안으로 전체 검증을 다시 실행했다. 기존 보조 장애물 최소 15개 회귀 조건도 확인해 각 구간의 중앙 핀을 두 개씩 배치했다. 기준을 낮추지 않았다.

## 보존 및 상태

운영 파일 변경은 `js/maps/cascade.js` 및 `index.html` 캐시 키뿐이다. 물리 엔진, 렌더러, 기본/갈래 서가/박자 분배기 맵, 음원 코드·MP3·크레딧, 원형 셔플·붓기·발사, 카메라·UI 코드는 시작 후보와 동일하다. 보존한 운영 파일 56개의 해시 목록은 [preservation.json](cascade-fast/preservation.json)에 있다. 배포 기준과 개발 분기의 기존 의도된 차이는 이전 맵·음원 정리 등의 커밋을 그대로 보존했다.

실서비스 운영 파일 26개를 기준 커밋과 새로 대조한 결과는 [deployment.json](cascade-fast/deployment.json)에 기록했다. 전체 회귀 검사는 셔플·오디오 전환/음소거·4종 추첨·50개 제한·설정·정지·결과·재현·맵 선택·미니맵·기존 바람을 포함한다. 이번 브라우저 검증은 데스크톱 50개 경기와 장치 애니메이션이며 모바일 실기기와 실제 스피커 청취를 새로 검증하지는 않았다. 유한한 위치/위상 표본으로 모든 연속 좌표·시간의 완전 증명을 주장하지 않는다.
