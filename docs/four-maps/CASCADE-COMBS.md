# 빗살 낙하 — 양쪽 대각 빗살과 직선 우회 경로 검증

사용자 요청에 따라 빗살 낙하만 지형 버전3에서4로 재구성했다. 공통 물리 엔진은 변경하지 않고 기존 moving/segment/pin 충돌을 사용했다.

## 코스

- y2100/4300/6500의 세 구간에 좌우 한 쌍씩 총6개의 빗살을 배치했다. 각 장치는 몸통1개·이빨21개로 구성하며 모든 이빨도 실제 충돌한다. 총132개의 동적 충돌체다.
- 장치들은6초 주기로 벽 밖에서 들어오고 물러나며 구간별 위상을2초씩 달리한다. 닫힌 자세에서 양쪽 대각 빗살의 가로 투영이 겹쳐 전폭의 수직 낙하길을 가린다. 양쪽 높이는300단위 엇갈려 두 끝이 같은 위치에서 공을 압착하지 않는다. 완전히 열린 자세에서는 두 장치 모두 벽 밖으로 물러난다.
- 기존30도 선반6개 줄18개는 그대로 유지하고 아래쪽2개 줄을 더했다. 기존 반송 가이드·쐐기·입구 가이드·핀은 새 장치와 겹치지 않도록 재구성했다. 최종 지형은 짧은 선반24개, 벽부터 이어지는 긴 대각 선반10개, 반사 핀36개, 동적 충돌체132개로 총202개다.
- 긴 선반5쌍은 열린 쪽이 번갈아 나타나도록 배치했다. 각 쌍의 가로 투영이 연속적으로 [36,964] 전폭을 덮어 **빗살이 전부 열려도 같은 x좌표로 끝까지 수직 낙하하는 길이 없다.** 아래쪽까지 선반과 핀을 이어 마지막 긴 무장애물 구간도 없앴다.
- 황동·목재 색 몸통, 밝은 이빨, 벽의 회수 홈과 리벳을 그렸다. 같은 물리 위치를 사용하며 벽 뒤로 들어간 부분은 화면에서도 숨긴다. [닫힘/열림 비교](cascade-combs/preview.jpg), [개폐 애니메이션](cascade-combs/preview.html).

## 끼임 문제 수정

초기 시안은 이빨9개, 간격62·두께 반경7이었다. 작은 공이 이빨 사이로 들어가 장치가 물러날 때 벽 쪽 틈에 끼면서 경계 이탈/깊은 관통이 발생했다. 반지름8·중력350·반발력0.92의25개/50개 조건 두 건에서 재현했다. 이 실패를 [summary.json](cascade-combs/summary.json)에 보존했다.

이빨21개·간격24·두께 반경8로 바꿔 이빨 사이의 열린 틈을8단위로 줄였다. 최소 공 지름16보다 좁아 공이 홈 내부로 들어가지 않는다. 실패한 두 시드를 회귀 검사에 추가했다. 경계·관통 판정을 완화하거나 위치를 강제로 되돌리는 처리는 추가하지 않았다.

## 위치와 개폐 검증

`node qa/four-maps/cascade-combs.cjs first`:

- 기본 반지름12에서 합법적인 출발 가로 범위 x48~952를 **1단위마다** 검사했다. 각 x를6초 주기의0/0.5/…/5.5초,12개 시점에서 낙하시켰다.10,860건이다.
- 반지름8/16, 각 구간 진입선 y750/2750/4950/7150/9750,12개 시점, 가로32단위 격자와 정확한 양끝 벽 위치를 더 검사했다.3,600건이다.
- 합계 **14,460건 전부 실제 장애물 접촉**, 첫 접촉까지 최대1.642초. 유한값·좌우 경계를 함께 검사했다.

각 고정 선반 쌍의 가로 범위를 연속 구간으로 병합해 빈 구간이 없음을 별도로 검사했다. 이는 단순 격자 외에도 수직선의 연속적인 전폭을 덮는 기하 조건이며, 장치의 움직임에 의존하지 않는다. 모든 가능한 초기 수평 속도·연속 운동 상태의 우승 확률까지 전수 증명했다는 뜻은 아니다.

`node qa/four-maps/cascade-combs.cjs full`:

- 반지름8/16, 시작 위상0/1.5/3/4.5초, 전폭32단위 격자 및 양끝 벽 위치로 **240건 전 구간 주행**, 전부 완주했다.
- 각 주행에서 장애물 접촉 최소18회, 최대 완주61.267초. 무접촉 우회나 경계 이탈이 없었다.

`node qa/four-maps/cascade-combs.cjs groups`:

- 실제 붓기·셔플 B/C/D 출발로50개 경기 **36회·총1,800개 공**을 검사했다.
- 모든 공이 최소10개의 서로 다른 장애물과 접촉했고,1등 공도 최소11개에 접촉했다. 전부 완주했고 강제 구조/스킬/포털/부스트 이벤트는0회였다. 최대 완주63.875초였다.

## 전체 회귀와 실제 화면

- 최종 `npm test`:**272개 통과**, 실패0개. `/tmp/cascade-combs-final-tests.log`.
- `node qa/four-maps/run-map.cjs cascade`:**108개 설정 조합·18개 실제 출발 정확 재현**, 실패0개. 공1/2/6/25/49/50, 반지름8/16·중력350/1500·반발력0.35/0.92 조합 포함. 극단 설정 최대155.459초이며 전부240초 상한 내 완주했다.
- 독립 장애물/장치끼리의 통과 간격과 벽 여유를120Hz로8초, 동작 주기6초 이상 검사해96단위 기준을 통과했다. 같은 빗살의 몸통·이빨은 연결된 고정 상대 위치라 내부 접합부는 간격 검사에서 제외한다. 벽 속으로 회수되는 장치의 벽 접합부도 의도된 접합이다. 해당 예외는 일반 장애물의 간격 조건을 완화하는 데 사용하지 않는다. 공이 접합부에 끼지 않는지는 작은 공의 실패 재현 및 전체 주행 검사로 확인했다.
- 인앱 브라우저에서 직접 붓기·발사·결과를 조작해 **50개 전원 완주,52.44초**를 확인했다(3배속 실행, 표시는 물리 시간). 진행 화면 표본은60FPS였으며 전체 프레임의 최소 성능을 보장하는 수치는 아니다. 브라우저 오류0개. [결과 화면](cascade-combs/result50.jpg).
- 기본 맵/갈래 서가/박자 분배기 지형, 공통 물리, 음원, 셔플, 입력, 카메라는 직전 커밋과 바이트 비교해 그대로임을 확인했다. 새 버전4 출발 기록은 정확 재현18건을 통과했고 지형이 다른 버전3 기록은 기존 서명 검사로 거부한다.

위치 검사는 명시된 범위의 격자·극단값·기하 조건을 확인한 것이며 모든 가능한 시드의 영구 무정체나 추첨 확률의 공정성을 보장하는 결과는 아니다. 실물 휴대폰과 새 대규모 추첨 확률 감사는 수행하지 않았다.
