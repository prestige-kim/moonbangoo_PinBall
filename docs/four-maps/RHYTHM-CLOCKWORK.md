# 박자 분배기 v4 — 기계식 리듬 공장

2026-10-14. 사용자가 v3의 벽 셔터와 대각 경사로가 빗살 낙하와 겹친다고 지적해, 맵 전체를 다른 동작과 디자인으로 교체했다. 시작 후보는 `ed65d96aabeb5c531d1ca8e9f3a1ae6a099a20b9`, 분기는 `codex/four-maps-local`이다. 다른 작업의 미커밋 배포 관리 문서를 덮지 않고 이 문서에 상태를 따로 기록한다.

## 완성된 구조

- 벽에서 출몰하던 셔터와 전폭 대각 경사로를 제거했다. 짙은 자주색·남색 판, 황동 원형 기계, 청록 타건 패드로 외형도 교체했다.
- 1700/4500/7300/10100 높이에 큰 6분할 분배 드럼 4기를 배치했다. 각 드럼은 실제로 충돌하는 지름 420의 회전 막대 3개를 같은 중심에 60도 간격으로 결합한 6개 날개다. 4.8초와 3.2초 주기를 번갈아 사용한다.
- 입구는 벽에서 시작하는 짧은 곡선 조각과 중앙 공급 통로다. 중앙 112 폭의 목을 거쳐 회전 날개 안으로 들어가도록 구성했다. 몸체별 충돌·위치·속도 조작이나 당첨자 유도 없이 지형으로 공급한다.
- 반지름 340의 원형 가이드는 위·아래에 실제 열린 출입구가 있다. 전체가 2.4초 주기로 12만큼 좌우로 미세하게 움직여 입구 끝에 공이 정지하지 않도록 했다. 모든 조각은 하나의 강체처럼 같은 변위·속도로 움직인다.
- 세 중간 구간은 작은 흔들림 포크로 가운데 직통과 양옆 우회를 만든다. 실제 경로 검사에서 양옆 이동 거리가 중앙보다 15% 이상 길고 통과 시간도 길다.
- 타건 패드 12개는 세로로 움직인다. 세 패드의 위상을 1/3주기씩 달리하고 면을 기울여, 위로 튀던 공이 옆으로 빠져나가도록 했다. 마지막 드럼 뒤에도 패드를 둔다.
- 움직이는 황동 노브 4개, 보조 핀 16개가 흐름을 보완한다. 총 충돌 부품은 202개다. 원형 가이드 조각 96개를 별도 ‘96개 장치’로 홍보하지 않으며 논리적 드럼은 4기다.
- 화면 가장자리 안개와 HUD 대비는 실행/완료 장면에서 박자 분배기를 선택했을 때만 어두운 팔레트에 맞춘다. 다른 맵과 설정/셔플 장면은 원래 스타일을 사용한다. 별도 음원은 추가하지 않았다.

## 검증 중 발견하고 고친 조건

1. 수평 패드 위에서 `clock-curved-feeders` 시드의 공 하나가 반복 점프했다. 패드를 기울여 이탈시키고 같은 50개 시드를 회귀 검사에 추가했다.
2. 고정 다이아몬드 꼭짓점의 정확한 중앙 낙하가 멈췄다. 좌우로 움직이는 포크로 교체했고, x=330/500/670의 분기 진입이 모두 빠져나가는지 검사한다.
3. 고정 원형 입구 끝으로 떨어진 작은 공 `x=640,y=742,r=8,phase=0`이 멈췄다. 원형 가이드 전체를 미세하게 이동시키고 기존 조건과 실제 입구 끝 조건의 완주 검사를 추가했다.
4. 처음에는 원형 가이드를 따라 드럼 날개를 모두 우회하는 우승 경로가 있었다(B-0 시드). 드럼을 확대하고 입구 공급 목을 만들며 노브를 출구로 옮겼다. 이후 단순 동적 장애물 접촉 조건에 더해 **우승자의 드럼 날개 접촉**을 요구한다. 통과를 위해 이 조건을 낮추지 않는다.
5. 스타일 캐시 키는 이 저장소가 검사하는 `hand-<sha256 앞 12자리>` 규약을 유지한다. 테스트를 바꾸어 캐시 규약을 완화하지 않았다.

## 검증 명령과 증거

최종 수치·코드 해시는 [summary.json](rhythm-clockwork/summary.json), 행별 원시 결과는 로컬 `qa/four-maps/results/clockwork-release/`와 `qa/four-maps/results/rhythm.json`이다. 시안의 예전 통과 결과를 최종 코드 결과로 재사용하지 않는다.

- `npm test`: 전체 회귀 검사. 지형 버전 4, 4개 드럼, 실제 날개의 결합, 직통/우회 길이, 물리적 박자 차이, 1..50개 완주와 재현, 멈춤 회귀, 9.6초 주기 간격, 렌더러의 상태 불변성을 포함한다.
- `node qa/four-maps/run-map.cjs rhythm`: 개수 1/2/6/25/49/50, 반지름 8/16·중력 350/1500·반발력 .35/.92 극단 설정 및 기본값의 108건. 실제 출발 B/C/D 기록 18건 정확 재현 및 기본 50개 성능 5건.
- `node qa/four-maps/rhythm-clockwork.cjs positions qa/four-maps/results/clockwork-release`: 기본 반지름의 모든 정수 x와 24개 위상, 작은/큰 공·양벽 포함 30개 x·각 모듈 진입 높이 800/3600/6400/9200의 접촉 검사.
- 같은 명령의 `full`: 작은/큰 공, 양벽 포함 30개 x, 네 위상의 전체 코스 240건.
- `groups`: 50개 경기 B/C/D 각 12개 시드. 모든 공의 지형 접촉, 세로 패드·드럼의 실제 접촉 이벤트, 우승자의 실제 드럼 날개 접촉 확인.
- `rotors`: 기본값과 8개 극단 설정의 50개 경기에서 매 틱 회전 날개의 잔여 중첩 깊이, 벽 이탈, 유한값, 완주 검사. 팔 길이에 맞게 근접 검사 범위를 250으로 확장했다.
- 독립 장애물 간 최소 간격 96을 유지한다. 접합된 곡선 조각 및 같은 강체의 날개 접합은 기존 assembly 예외를 사용하며, 서로 다른 기계 사이의 간격을 예외로 숨기지 않는다.
- 실제 브라우저에서 검정 공을 포함한 50개 붓기·발사·진행·결과를 확인한다. [진행 화면](rhythm-clockwork/race50.png), [완주 화면](rhythm-clockwork/result50.png), [장치 미리보기](rhythm-clockwork/preview.html).

## 기존 기능·배포 기준 보존

배포 기준은 `5d25319ddd2d352cf35e314da27329c97daec397`이며 원격 main을 새로 조회·fetch하고 후보 이력에 포함됨을 확인했다. 실서비스 운영 파일 26개를 새로 대조한 [배포 파일 증거](rhythm-clockwork/deployment.json)를 남겼다. 이번 작업에서 Pages 작업 API의 실행 기록을 별도로 재조회하지는 않았다.

시작 후보와 운영 파일 53개가 [동일 해시](rhythm-clockwork/preservation.json)다. 물리 엔진, 음원·MP3·크레딧, 원형 셔플/붓기/발사, UI 로직, 추첨, 카메라, 다른 세 맵 지형은 그대로다. 렌더러의 박자 분배기 전용 분기만 교체했고 [다른 세 맵의 30개 렌더링 명령 비교](rhythm-clockwork/render-preservation.json)가 동일했다. CSS 추가는 rhythm 선택과 running/finished 장면을 모두 만족할 때만 적용된다.

v3 출발 기록과 지형을 혼용하지 않도록 `rhythm.version`을 4로 올렸다. 기존 맵·기록의 버전과 동작은 바꾸지 않았다. 과거의 셔터 개수·대각 경사로 조건은 요청에 맞춰 새 구조 조건으로 교체했으며 완주·간격·오류·구제 금지·재현 기준은 유지했다.

다른 작업의 `qa/fairness/freeze.cjs`, 미추적 `AGENTS.md`, `docs/RELEASE_MANAGEMENT.md`, fairness confirm 결과는 수정·stage·commit하지 않는다. 모바일 실기기와 실제 스피커 청취, 모든 연속 좌표·위상·시드에 대한 완전 증명은 이번 검증 범위가 아니다. 브라우저 창 크기 변경은 실기기 검증과 구분한다.

요청 범위는 로컬 구현이다. push, PR, main 병합, 배포는 하지 않는다. 최종 후보는 이 문서를 포함하는 로컬 커밋이다.

## 최종 결과와 로컬 상태

- 전체 테스트 **277/277**, 실패 0. 위치·위상별 첫 충돌 **27,480건**, 전체 코스 **240건**, 50개 경기 **36회**, 회전 날개 매 틱 검사 **9개 설정**, 개수/극단 설정 **108건** 모두 통과했다. 첫 충돌 검사는 전체 코스 완주 검사와 구분한다.
- 36회 경기에서 모든 공은 최소 18개 지형에 접촉했고, 우승자는 최소 3개 드럼 날개와 접촉했다. 기본 설정의 이 표본에서 마지막 공 도착은 최대 62.58초였다. 극단 설정 108건은 최대159.63초로 모두 완주했다.
