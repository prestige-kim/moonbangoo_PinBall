## 각 연출의 적용

| 화면 | 적용 방식·확인 |
|---|---|
| 공통 시작 화면 | 기존 스튜디오·정지된 통 배치를 유지한다. 맵 선택 전 공통 환영 연출이다. |
| 맵 선택 카드 | 각 맵의 배경 이미지를 깔고 기존 미니 지형을 겹쳐 그린다. 이미지 로딩 후 카드도 다시 그린다. |
| 준비 | 선택한 맵의 배경을35%로 섞는다. 설정 패널 뒤의 기존 흐림 처리는 유지한다. |
| 붓기·셔플 | 준비의35%에서100%로 자연스럽게 이어진다. 공·셔플 상태·출발 시점은 바꾸지 않는다. |
| 발사 전환 | 선택한 맵 배경과 같은 이미지로 만든 보드를 사용하며 도착 시 실제 경기 보드로 연결한다. |
| 경기 | 중앙은 조용하게, 가장자리는 상세하게 표현한다. 세로 스크롤은 이미지를 상하 반전 반복하며 불투명 캐시와1px 겹침으로 연결부의 가는 선을 줄였다. |
| 결과·다시 설정 | 현재 맵 배경을 유지하고 다른 맵 선택 시 해당 이미지로 갱신한다. |
| 모바일 | 390px 폭의 네 맵 준비 화면·가로 넘침0, 태엽 공장의 터치 발사와 경기 진입을 확인했다. |

배경 이미지는 맵당 한 번 로딩해 공유한다. 보드 래스터 캐시는 현재 타일 한 장만 보유하고 밀도2로 제한한다. 보드 바깥 배경은 종횡비를 유지하며 화면을 채운다. 이미지가 없거나 로딩 중이면 기존 절차적 패턴으로 동작한다. 배경 장식은 충돌체가 아니다.

## 캐시 보강과 실제 검토

기존 발사 보드 캐시 키는 시드·테마·높이만 사용했다. 같은 시드의 맵 전환과 이미지 지연 로딩을 구분하도록 맵ID·배경 revision을 추가했다. 준비 화면의 정지 프레임 캐시도 같은 기준으로 갱신한다.

- [최종 브라우저 기록](browser.json): 네 맵의 준비·셔플·발사·경기·결과20개 조합에서 렌더러의 맵과 실제 이미지 URL을 검사했다. 모두 일치, 콘솔 오류0. 맵별50개 완주 확인.
- 지연 로딩을 실제로 막았다가 해제했을 때 배경 revision4→6, 준비 화면 캐시와 실제 픽셀 이미지가 바뀌는 것을 확인했다. 이전의 빈/다른 배경이 남지 않았다.
- 도서관·협곡·태엽 공장은 동일한 background-common-seed로 전환했다. 발사 보드 키가 각 맵ID와 revision으로 바뀌었다. 별도 단위 검사에서도 동일 시드의 맵 변경·이미지 로딩 후 캐시 재생성을 확인했다.
- [가독성 조정 후 정상 속도 전체 흐름](browser-before-seam-fix.json)은 네 맵 모두 실제 입력·정상 경기·결과까지 통과했다. 최종 연결부 보강 후 browser.json은 같은 실제 입력·준비·발사·초반 경기를 검사하고 경기 뒷부분만 고정 스텝으로 빨리 마무리했다. 이를 시간 균형 검사나 실제 소요 시간 측정으로 사용하지 않는다.
- 로컬 검사 서버의 SVG MIME 설정을 바로잡아 최종 화면의 기존 로고도 올바르게 표시되도록 했다. 운영 SVG·로고 파일은 변경하지 않았다.
- 생성 이미지와 실제 준비·발사·경기 화면을 눈으로 확인했다. 최종 스크린샷은 미리보기에서 맵별·단계별로 볼 수 있다.
