# 맵별 긴장감 측정과 도서관 후반의 별도 시안

2026-10-15. 요청한 순서대로 **현재 맵 측정 → 한 구간 시안 → 효과·시간 확인 → 나머지 방향 판단**까지 진행했다. 원본 운영 파일은 변경하지 않았고 push·병합·배포하지 않았다. [로컬 비교 도구](index.html).

## 결론

도서관 후반 시안은 작은 개선 신호는 있으나 **본 적용·다른 맵 확대를 권할 정도의 효과는 확인하지 못했다.** 추가 지형 조정이나 반복적인 대규모 검사는 하지 않는다.

네 맵 모두 초반 우세가 항상 유지되는 구조는 아니었다. 다만 기본6개 조건의 도서관과 공장에서는 초반 선두 우승이 상대적으로 많았고, 도서관은 후반 선두가 굳어지는 경향이 보였다. 평균 교체 횟수만 늘리는 대신 **중요 구간에서의 재접근·역전과 화면에서의 가독성**을 함께 다뤄야 한다.

## 기준과 측정 조건

시작 HEAD `070676aea36f87dafee24df5f53f2904148067c3`, 원격main·최근 성공 Pages 소스는 시작/종료 모두 `a41acdf21c98df49e746163e6a49c4f9abbff096`. 실제 서비스53파일을 새로 해시 대조해 모두 일치했다(baseline-service.json). 작업 분기는 이 기준을 포함한다. 운영 지형은 로컬의 연못v2·도서관v9·협곡v7·공장v5이며, 서비스 협곡v6와 구분한다.

- 기본 설정: 크기12·중력620·반발력0.72·스킬OFF.
- 현재 맵: 4맵 × 공6/25/50 × 기존 B/C/D 출발 × 시드6개 = **216경기**. 각 맵54경기, 각 공수18경기다.

- 모델의 실제 붓기·셔플·출구 의미를 쓰는 capture로 만든 같은 원본을 맵마다 commit했다. 맵 사이와 기존/시안 사이 출발 슬롯의 동일성을 assert로 확인했다.
- 실측 보정: 공6개12경기1.83초·공50개12경기2.94초. 이를 근거로 본216경기1~2분을 안내했고 실제45.21초였다. 시안54경기는10.19초였다.
- 기본맵 시간 기준은 수정 전 원본에 고정했다. 다만 이번 검사는3공수뿐인 탐색 표본이므로 기존의 전체1~50개 중앙값·전체1500경기 p95 승인 검사와 동일하지 않다.

## 순위 지표의 정의

첫 공이 결승에 도착하기 전까지 10Hz로 실제 y 순서를 읽었다. 공동 선두를 제외하고 후보가0.45 **시뮬레이션 초** 이상 유지돼야 선두 교체로 기록한다. 초기 군집 흔들림을 줄이기 위해 앞선 공의 최고 도달 진행률10% 이후부터 교체를 센다. 체크포인트25/50/75%는 앞선 공이 해당 높이를 처음 통과한 표본의 즉시 선두·상위3개를 기록한다.

중반은25~75%, 후반은75~100%다. 공 한 개의 같은 높이 왕복을 진행으로 부풀리지 않도록 구간 분류에는 선두의 최고 도달 진행률을 사용한다. 지표는 영상 알림이나 diagnostics.leadChanges를 읽은 것이 아니다. 현재 화면 알림은0.45실시간 초 유지·7실시간 초 간격·최대3회라, 특히 배속에서는 측정치와 다르다. 단순 세로 선두와 통로별 실제 남은 거리는 다를 수 있고, 10Hz보다 빠른 교체는 놓칠 수 있다.

### 기본맵의 기존 구제 동작

현재216경기는 모두 완주했고 모든 공이 고체 장애물에 접촉했다. 유한값·벽 범위 오류0이다. 추가3맵은 구제/스킬/순간이동/부스트 사건0이다.

그러나 연못54경기 모두 기존 특수 사건이 기록됐다. 원자료의 errors.forbidden 합계는1546으로, 이 필드는 추가 맵에 적용하던 금지 분류를 기본맵에도 동일하게 센 값이다. 첫 동일조건 `final-holdout-v2-0-6-B-0`을 별도로 읽어 재현했을 때11건 모두 rescue였다. 다른 사건별 분해는 원자료에 없으므로1546건 전부를 세부 유형까지 검증했다고 주장하지 않는다. 이 원자료를0으로 고치거나 실패 기록을 삭제하지 않았다.

기본맵에는 기존 정지 구제 메커니즘이 있으므로 여기서 측정된 순위 변화를 모두 순수 장애물 추월이라고 해석할 수 없다. 이번 시안은 기본맵을 수정하지 않는다. 향후 기본맵의 정지/구제 발생 위치를 먼저 분리해야 한다.

## 첫 시안 선정과 형상

연못은 중반 교체가 가장 적었지만 기존 구제 동작의 영향 분리가 필요하다. 도서관은75% 선두 우승률이 가장 높고, 마지막25%의 선두 교체 합계54회로 연못123·협곡121·공장137회보다 적었다. 따라서 도서관의 후반 한 구간을 우선 선택했다. 사전 예상했던 모든 맵의 중반에 일괄 추가하는 계획은 측정 결과에 맞춰 보류했다.

별도 JS 플러그인만 기존 도서관을 복제해 **검토용v10**으로 만든다. 원본v9 객체와 운영 파일은 그대로다.

- 제거: 중앙 책받침1개, `(500,10160)`, 길이360·각도−0.55·좌우진폭60.
- 추가: `(350,10080)`과`(650,10320)`의 책받침2개. 길이250·두께8·각도±0.38·좌우진폭55, 속도1.25/0.9와 다른 위상.
- 같은 높이에서 모두 함께 기다리는 대신, 두 갈래로 흐르고 다른 도착 시점에서 재합류할 기회를 만든다. 기존 서가·바람·결승과 공통 물리를 유지한다.
- 새 타입·공 ID/색/순위 판별·추격 보정·추가 구제·순간이동·강제 완주를 넣지 않았다. 기존 장애물 이미지와 배경을 그대로 사용한다.
- 두 새 책받침의 수평 이동 전 범위에서 벽 통과 여유96px 이상, 서로의 세로 외곽 간격96px 이상을 계산으로 확인했다. 이것만으로 모든 다중 충돌의 완주를 증명하는 것은 아니다.

## 기존 기능과 화면 확인

전체 테스트301개 통과, 실패/취소/건너뜀0(tests.log). 새 검사3개는 원본 객체·다른 맵/기존 장애물 보존, 벽/책받침 간 간격, 원본v9 기록의v10 거부와 새v10 기록의 완주·정확 재현을 검사한다.

별도 페이지에서54개 모든 사례의 선두 흐름을 선택할 수 있다. 기본 선택은 첫 시드이며 좋은 결과만 고르지 않았다. 기존v9·시안v10 각각 실제 브라우저 재현의 모든 도착 ID·시간이 해당 시뮬레이션 원자료와 정확히 일치했다. 준비/경기/결과·후반 지형·390px 모바일 넘침0·콘솔 오류0을 확인했다(browser.json). 지형 정지 미리보기는 이미지 로딩 후 다시 그려 장애물 재질을 확인한다. 검토 iframe의 저장 쓰기는 메모리 저장으로 분리해 원본의 직전 경기 기록을 시안 기록으로 덮지 않는다.

도서관v9 출발 기록을 v10에서 그대로 재생하지 않는다. 같은 셔플 원본에서 v10용 서명을 가진 기록을 새로 만들며 슬롯 동일성을 검사한다. 원본 서비스와 로컬 루트는v9이므로 기존 도서관v8/협곡v5 기록 거부 정책도 바뀌지 않는다. 별도 시안의v10 기록은 본 적용 승인이나 배포 기록이 아니다.

## 나머지 맵의 적용 방향 결정

- **연못 정원:** 장애물 추가 전에 기존 구제 사건의 위치·지속 시간·선두 영향부터 분리한다. 이후 중반의 교체 없는 경기에서 분기/재합류를 검토한다. 시간 기준인 원본은 고정해 둔다.
- **바람 도서관:** 현재 후반 시안은 채택 보류. 다음 설계가 필요하다면 기본6개에서 선두와 추격 공이 실제로 재접근하는 구간, 특히 중반의 분기·재합류를 우선한다. 동일한 끝부분 장애물을 더 쌓지 않는다.
- **빗살 협곡:** 이미 중반 교체가 많고, 로컬v7의 기존 시간 균형 실패가 남아 있다. 추가 지형보다 긴 바위턱의 재접촉 체류와 시간 문제를 먼저 다뤄야 한다. 이번에 수정하지 않았다.
- **태엽 공장:** 중반 교체 없는 경기는0/54였다. 전체 장애물 추가보다 기본6개에서 특정 통로/박자가 연속 유리한지 좁혀 보고, 실제 추월을 화면에서 읽기 쉬운지 확인한다.

화면의 최대3회·7초 제한 때문에 실제 교체가 전달되지 않을 수도 있다. 이것을 실제 추월 부족과 혼동하지 않고 후속 시각 검토 대상으로 남긴다. 알림을 늘리는 것만으로 물리적 긴장감이 개선됐다고 주장하지 않는다.
