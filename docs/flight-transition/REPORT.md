## 결론과 전환 방향

**셔플하던 종이 배경 아래에서 같은 크기의 놀이판이 드러나고, 공이 그 위의 자기 출발 위치로 모이는 방식**을 제안한다. 어른뭉방구의 종이·인쇄·금박 배경을 공간 연결에 사용하고, 게임판을 향한 큰 확대와 독립된 아치형 장식판 등장을 제거한다.

이번 시안은 카메라를 고정한 차분한 탁상 놀이 방향이다. 기존처럼 공 무리를 따라 크게 날아가는 역동성은 줄어든다. 자연스러움 자체는 사용자의 영상 검토가 필요한 디자인 판단이며, 자동 검사는 좌표·잘림·인계의 객관적인 조건을 보완한다.

## 어색함의 확인된 원인

- HandFlight.begin의 기존 initial 판은 화면 오른쪽 밖, 폭 약32% 이하의 작은 스케일이다. cameraAt은 초반0.66배로 더 물러났다가 진행65% 이후 도착 스케일까지 확대한다. 1280×800에서 마지막35% 동안 약6.02배, 390×844에서 약4.53배 확대됐다.
- 화면 전체의 배경은 화면 좌표에 고정된 반면, 작은 게임판·공은 별도의 장면 행렬로 움직인다. 같은 원본 삽화가 서로 다른 크기와 위치로 겹쳐 서로 다른 공간처럼 읽힌다. 이 부분은 코드·프레임을 바탕으로 한 시각적 판단이다.
- 전환 중에는 cinemaBoard 캐시와 아치 프레임, 실제 경기에서는 Renderer의 보드를 사용한다. 기존 HandFlight.render는 p=1에서 배경과 전환판을 한 번에 그리지 않고 공만 남긴다.
- 특히 **모션 감소**에서는 view.amount=0이 유지되어 targetBoard의 아치가 끝까지 남았다가 p=1에서 사라진다. 실제 캡처에서 마지막 프레임의 화면 변화 비율18.18~24.67%를 재현했다.
- 같은 모션 감소의 기존 경로는 카메라가 고정됐는데도 긴 속도 접선을 유지해 일부 공이 화면 밖으로 나갔다. 잘림은 게임의 탈락이 아니라 전환 중 화면 밖 렌더링을 의미한다.

## 시안의 단계별 기획

| 단계 | 일반2.8초에서의 시간 | 구현 |
|---|---|---|
| 발사 연결 | 0~약0.11초 | 마지막에 보인 공의 좌표·반지름·속도로 시작한다. 화면 전체의 기존 맵 배경을 유지한다. |
| 놀이판 등장 | 약0.11~1.46초 | 진행4~52%에서 종이 덮개를 smoothstep으로 걷는다. 실제 경기판을 실제 Renderer로 그리므로 별도의 작은 판·아치·캐시를 등장시키지 않는다. |
| 공 정착 | 중·후반 | 카메라·판의 위치와 크기는 고정한다. 발사 방향의 짧은 관성 후 각 공이 확정된 자기 출발 위치로 도착한다. 공의 목표 슬롯이나 ID를 재배치하지 않는다. |
| 경기 인계 | 마지막 구간 | 기존 HUD 공개 흐름에 연결한다. 배경은 이미 실제 경기 화면이며, p=1에서 공 좌표·반지름을 정확히 인계한다. 경기 계산은 원래 시점에 시작한다. |

기존 긴 관성 경로를 그대로 두고 카메라만 고정한 시안에서는 화면 밖 이탈이 생겼다. 기본맵 실험에서 중간 잘림9790개 공-프레임 표본, 최대373px를 확인했다. 이를 피하려고 데이터나 허용치를 완화하지 않고, 전환용 pose에 짧은 C2 관성 창과 작은 방향 추진을 적용했다. 출발 속도는 이어지고 끝 속도는0이며, 출발 지연도 최대0.12→0.04초로 줄였다. 물리 엔진의 공 속도·위치를 바꾼 것이 아니다.

`first-prototype.json`은 중단한 초기 카메라 추적 시안의 일부 기록으로 **최종 결과가 아니다**. 고정 카메라만 사용한 실험과 최종 시안을 혼동하지 않는다. 최종 결과는 browser.json 및 verification.json의 파일 해시를 기준으로 한다. pilot.log는 기본맵 국소 확인이며 최종12조건을 대체하지 않는다.

## 맵별 적용 판단

| 맵 | 배경 연결과 확인 | 주의점 |
|---|---|---|
| 연못 정원 | 청자색 연잎·금갈색 선화 위에 밝은 경기판을 드러낸다. 녹색 공과 배경의 대비를 기존 중앙 베일로 유지한다. | 수면을 추가로 움직이지 않는다. 배경 움직임과 공 낙하가 중첩되지 않는다. |
| 바람 도서관 | 책·책갈피·종이 소재와 실제 책받침 지형이 같은 인쇄 재질로 이어진다. 초기 위치·슬롯은 다른 맵과 같은 원리다. | 새로 날리는 종이 입자를 넣지 않았다. 실제 바람 장애물의 표시와 전환 장식을 혼동시키지 않는다. |
| 빗살 협곡 | 테라코타 층리 배경 아래에서 기존 빗살 지형이 있는 판을 드러낸다. 새 바위 받침과 기존 빗살은 실제 Renderer로 이어진다. | 기존 협곡v7의 지형·경기 시간 문제를 전환 수정으로 해결했다고 주장하지 않는다. |
| 태엽 공장 | 밝은 종이 배경과 남색 경기판의 가장 큰 명도 차이를 전반 디졸브에 분산한다. 황동 공장 장애물을 최종과 같은 렌더러로 그린다. | 모션 감소의 기존 마지막 화면 교체가 가장 컸다. 시안은 종료 직전 배경 교체를 제거했지만 밝음→어두움 변화 자체는 남는다. |

새 에셋·효과를 만들지 않고 네 맵에 같은 전환 문법을 적용한다. 맵 구분은 기존 배경·장애물 재질·실제 지형으로 유지한다. 실제 출발 구간이 길어 처음에는 장애물이 보이지 않는 맵이 있다. 이를 숨기려고 경기 지형을 위로 당기거나 출발 좌표를 바꾸지 않았다.

## 검증 범위와 결과

최종 시안의 브라우저 조건은 다음12개다. 각 조건에서 같은 실제 발사를 현재/시안 두 방식으로 다시 그려 비교했다.

- 네 맵 × 데스크톱1280×800·공50개.
- 네 맵 × 모바일390×844·공6개·터치 에뮬레이션.
- 네 맵 × 모션 감소1280×800·공6개.
- 각 변형의 진행0~1을601점으로 샘플링했다. 중간 구간20~90%에서 공 반지름까지 포함해 화면 밖0.5px 초과를 센다. 표본 수는 고유 실패 공 수가 아니라 **공×프레임** 수다. 시작/끝은 개별 좌표 조건으로 확인한다.

| 맵 | 일반 데스크톱 후반 확대 배율, 현재→시안 | 모션 감소 중간 잘림 표본, 현재→시안 | 모션 감소 종료 프레임 픽셀 변화, 현재→시안 | 시안 완주 |
|---|---:|---:|---:|---:|
| 연못 정원 | 6.02 → 1.00 | 316 → 0 | 18.18% → 0.00% | 62/62 |
| 바람 도서관 | 6.02 → 1.00 | 210 → 0 | 24.04% → 0.00% | 62/62 |
| 빗살 협곡 | 6.02 → 1.00 | 230 → 0 | 23.35% → 0.00% | 62/62 |
| 태엽 공장 | 6.02 → 1.00 | 55 → 0 | 24.67% → 0.00% | 62/62 |

일반 데스크톱·모바일의 현재/시안은 모두 중간 잘림0이었다. 모션 감소의 현재 실패는 위 표와 같고 시안은12조건 모두 잘림0이다. 시안 마지막35%의 확대는 모두1배, 끝 좌표·반지름 오차 최대약1.3e-13px, 물리 상태·시간·틱·출발 기록은 비행 검토 전후 동일했다. 각 조건을 실제 경기·결과까지 이어248개 모두 완주했다. 뒷부분은 고정 스텝으로 빠르게 마무리했으므로 경기 시간 비교나 FPS 증거가 아니다.

종료 프레임 변화 비율은 p=.9999와p=1의 **게임 캔버스+전환 캔버스 합성**을 비교해 RGB 평균 차이12/255 초과 픽셀 비율을 센 것이다. HUD·CSS 오버레이는 포함하지 않는다. 표의0%는 이 기준에서 전환 마지막 순간의 교체가 없어졌다는 뜻이며 전체 게임 화면이 영원히 픽셀 동일하다는 뜻이 아니다.

실제 경기 공 렌더러로 그린 별도 기본맵50개 인계 검사에서는 평균 차이0.117/255, 변화 픽셀 약0.217%가 남았다([실제 도구 검사](lab-check/report.json)). 공의 좌표·반지름은 같지만 화면 좌표로 그리는 cinematic 구체/표식과 월드 좌표로 그리는 경기 구체/표식의 래스터 경로가 다르다. 차이 원인에는 이 경로가 기여할 것으로 판단하지만 모든 잔차를 분해하지는 않았다. **실제 경기 인계가 픽셀 단위로 완전히 같다고 주장하지 않는다.** 본 적용 시 공의 마지막 렌더 경로를 통일할 부분으로 남긴다.

- 전체 테스트298개 통과, 실패·취소·건너뜀0([로그](tests.log)). 새 검사3개는 네 맵·공수6/25/49/50·화면3종·모션2종의96조합에서 출발 연속성·정확한 도착·물리/RNG 불변, 화면 크기 변경 시 인계 연속성, 원본으로 복원·루트 미적용을 검사한다.
- [비교 도구 검사](lab-check/report.json): 비교 영상16개의 로딩·길이·재생 확인, 직접 입력 시안에서 실제 붓기·원형 셔플·발사 후 같은 상태의 현재/시안 전환·재생 성공, 콘솔 오류0. 원본 루트에는 FlightPrototype이 없다.
- 네 맵의 중간 실제 이미지와 모바일·모션 감소 화면을 시각 검토했다. 각 맵은 공·재질·색을 유지하고, 급확대 대신 판의 등장과 공의 정착이 보인다. 판단용 영상은61개 합성 프레임을 약2.85초로 인코딩했다. 기기 성능이나 실제 녹화 FPS를 나타내지 않는다.
- 최종12조건의 실제 처리 합계는 약156초였다. 기본맵 예비 확인으로 경로·판 위치 문제를 먼저 정리하고, 확정한 시안은12조건을 한 차례 검사했다. 별도 대규모 시간·극단 설정·확인용 시드 검사는 추가하지 않았다.

## 보존·호환성·상태 기록

시작 HEAD는 `dc628edcb758a816df9a98de49de4800d0f2795d`, 검토 가능한 시안 커밋은 `782b4de`다. [검증 파일 해시](verification.json)는 이 커밋과 같다. 실행 당시 시안 파일은 시작 HEAD 위의 미커밋 상태였으며, 실행 후 내용 변경 없이 커밋했다. browser.json의 source는 당시 시작 HEAD 기록으로, 루트 게임이 바뀌었다는 의미가 아니다.

시작과 종료에 새로 조회한 원격 기본 브랜치main 및 최근 성공 Pages 소스는 모두 `a41acdf21c98df49e746163e6a49c4f9abbff096`다. [실서비스53개 파일](baseline-service.json)을 새로 해시 대조했고 모두 일치했다. 작업 분기가 이 기준을 포함한다. 루트의 기존 운영·자산·설명75개 파일은 시작 HEAD와 전부 동일([보존 증거](preservation.json))하다. 변경은 별도 QA·테스트·검토 페이지·증거 추가뿐이다.

맵 버전은 연못v2·도서관v9·협곡v7·공장v5 그대로다. 물리·셔플 입력·추첨·RNG·출발 슬롯·맵 이름·음원·재현 서명은 바꾸지 않았고, 출발 기록 호환성도 바꾸지 않았다. 기존 도서관v8·협곡v5 기록에 대한 거부 정책은 유지된다. 다른 작업의 fairness freeze/confirm 파일, AGENTS.md, 미추적 RELEASE_MANAGEMENT.md 다섯 파일은 수정·stage하지 않았다. 배포 상태 기록은 이 보고서에 분리했다.

미검증/한계: 모든 시드·모든 제스처·모든 설정·실물 휴대폰·TV·전체 브라우저를 보장하지 않는다. 시안은16개 비교 영상과12개 실발사 조건,96개 합성 불변 조건의 증거를 제공한다. 모션 감소는 화면 이동을 줄이되 공의 위치 이전 자체는 남긴다. 직접 시안은 프레임 비교를 위해 경기 계산을 정지하므로 HUD·순위/미니맵은 실제 경기처럼 갱신하지 않는다. 원본 게임의 새 배포 후보가 아니며, 기존 협곡v7 시간 균형 실패도 유지한다.
