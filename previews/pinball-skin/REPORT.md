## 변경

관/셔플의 `orbSprite`와 경기의 `marbleSprite`가 서로 다른 유리 구슬 재질을 그리던 구조를 제거했습니다. 이제 대기 유리관, 붓기, 셔플, 비행, 실제 경기, 완주 표시와 확대 우승 공이 `P.Pinball`의 같은 사진 스프라이트를 사용합니다. 비행의 gameBlend 값에 따른 재질 크로스페이드와 별도 회전 하이라이트를 제거했습니다. 참가자별로 사진을 다시 칠하지 않습니다. 이름/ID/참가자 색상 메타데이터는 유지하며 공 본체는 모두 은색 강철입니다.

렌더의 중심/반지름/원근 변형/투명도는 기존 좌표를 사용합니다. 스프라이트의 불투명 원 반지름은128 중25로 기존 `r*5.12` 그리기 크기와 정확히 대응합니다. 원본 알파의 미세한 반투명도를 금속 밑색으로 보정하고 원형 클리핑을 적용해, 표시된 공 경계와 충돌 원을 맞췄습니다.

물리 엔진, 맵, 셔플/발사 판정, 실제 셔플 출발 위치 연결, 시드, 규칙, 순위·도착 시간 계산, 결과 UI는 수정하지 않았습니다.

## 원본과 실제 품질

실제 사진을 가져와 사용했습니다. 재사용이 허용된 Lucasbosch의 [Polished steel ball 60mm diameter](https://commons.wikimedia.org/wiki/File:Polished_steel_ball_60mm_diameter.jpg) 실물 사진을 내려받았습니다. 원본4538×3030. 실제27mm 핀볼 제품 사진으로 확인된 자료는 아니며, **실물 광택 강철 구체의 사진**을 핀볼의 크롬 표면으로 사용했습니다. 제품 사진 사이트의 원본은 접근 제한으로 확보하지 못했습니다. 게임 공의 물리 크기를60mm로 바꾼 것은 아닙니다.

내장 imagegen으로 배경/접지 그림자를 제거하고, 카메라가 비친 부분을 중성 스튜디오 반사로 정리했습니다. 최종 PNG 파일 실측은 **1254×1254 RGBA, 약1.3MiB**입니다. 프롬프트에서2048을 요청했지만 최종 출력 해상도가2048이라고 주장하지 않습니다. 원본/파생 이미지의 출처와CC BY-SA3.0 표기는 [에셋 라이선스](../../assets/pinball-chrome-photo.LICENSE.md)에 보존했습니다.

[최종 이미지](../../assets/pinball-chrome-photo.png). 사진의 가운데 불투명 구간은 x90/y80/1073×1094입니다. 바깥의 추출 잔여 픽셀은 제외하고 양 축을 원형 반지름에 맞춰 그립니다. 원래 사진의 반사/표면 디테일을 유지하며 확대 공에도 같은 이미지를 사용합니다.

## 성능·로딩

- 64/128/256/512/1024의 최대5개 스프라이트를 화면 크기×DPR에 맞춰 선택합니다. 500개 이름/색상을 위해500개 사진 복사본을 만들지 않습니다.
- 소스 이미지는 한 번 로드/디코딩합니다. 알파 경계 분석은 로딩 때만 합니다. 모든 테마/모션 설정에서 동일 소스와 공통 캐시를 재사용합니다.
- 최대로 생성된5개 캔버스의 RGBA 메모리는 약5.33MiB이며, 원본 디코딩 메모리는 약6MiB입니다. 실제로 필요한 해상도만 지연 생성합니다. GPU/브라우저 자체 오버헤드는 이 계산에 포함하지 않습니다.
- 이미지 로딩 전/실패 시에도 같은 중성 강철 폴백을 사용합니다. 사진이 늦게 도착하면 대기 화면의 정지 캐시만 한 번 갱신하고 공 위치나 물리 시간을 진행시키지 않습니다.

## 500개 연속 입력 측정과 직접 마우스

다른 자동 검사가 끝난 상태에서1280×720, 고품질, 일반 모드의500개를10초 동안 계속 드래그했습니다. 598프레임, 평균59.81FPS, 프레임 p95 17.60ms, 최대33.40ms. 셔플 CPU 평균4.92ms/p95 15.00ms, 공 렌더 평균1.59ms/p95 2.60ms. 모두 벽 안에 유지되고500개 ID를 보존했습니다. 최악 상대 겹침0.000704. [측정 원본](benchmark.json). 전체 기기 성능을 대표하는 측정은 아닙니다.

8개에서는 실제 브라우저 마우스 이벤트로 중앙→왼쪽 드래그를 수행했습니다.9개 입력 샘플,13회 충돌, 위치 교환을 확인했습니다. 이어 공을 우측 상단 출구로 드래그하여 pointermove에서1회 발사됐습니다. 발사 시 위치·속도 연속, 경기 착지8개 ID 일치/오차0px. [마우스 증거](native-mouse.json), [셔플](shuffle-8.png), [경기](game-8.png).

[붓기→셔플→발사→경기 영상](flow.webm)은 실제 브라우저 캔버스를30FPS로 녹화했습니다. 영상의 제스처는 QA 합성 터치이며, 위 별도 마우스 검사와 구분합니다.
