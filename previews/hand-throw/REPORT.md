## 구현 방식

1. 시작하기로 기존 설정 패널을 엽니다. 게임 시작 후 기존 유리관 위치에서 같은 ID의 핀볼이 약 0.8초에 걸쳐 중앙으로 나옵니다. 사용자가 던지기 전까지 자동 발사하지 않습니다.
2. `shuffle.js`의 개별 원형 물체는 자신의 좌표·속도·충돌 반지름·ID를 유지합니다. 포인터 근처에 거리 제곱 가중치로 속도 전달과 약한 인력을 가하고, 움직이는 손의 작은 부드러운 접촉 영역으로 물체가 입력 경로 주변을 돌아가게 합니다. 가까운 핀볼이 먼저 반응하고 나머지는 관성과 충돌로 따라옵니다. 좌표를 손에 붙이거나 집합 전체에 같은 이동량을 적용하지 않습니다.
3. 약한 중력, 접선 마찰, 지수 감쇠, 약한 중앙 복귀력, 화면 경계 반발을 적용합니다. 손의 속도가 오래되면 힘을 감쇠합니다. 놓기·취소 시 포인터 힘만 제거하고 현재 좌표·속도는 보존합니다. 고정 사인파, ID별 반복 힘, 입력과 무관한 회전력은 없습니다.
4. 120Hz 고정 시간과 적응형 하위 스텝, 공간 해시 이웃 검색·반복 충돌 해소를 사용합니다. 경기 엔진의 충돌 방식과 최적화 원칙을 별도의 시각적 셔플 모듈에 적용했습니다. 경기 물리를 수정하지 않았습니다.
5. 중앙 집합 반경은 `0.185S`, 핀볼 반경은 `min(0.034, 0.125 / sqrt(N)) × S`입니다. 같은 `body.r`로 표시와 충돌을 처리합니다. 500개도 개별 물체·ID를 유지합니다.
6. 마우스·터치는 `shuffle-input.js`의 단일 Pointer Events 모델을 사용합니다. 포인터 캡처와 창 수준의 해제를 처리하고, 두 번째 접촉이 들어오면 현재 입력을 취소한 뒤 접촉이 모두 끝날 때까지 막습니다. 포커스 상실·숨김·취소·회전/크기 변경은 발사 없이 복귀합니다. `touch-action:none`은 셔플 중 시네마 캔버스에만 적용합니다.

### 최종 발사 기준

`throw-gate.js`의 공개 상수 `P.THROW_THRESHOLDS`에 기준을 모았습니다. 브라우저 검수 후에도 요청한 초기값을 유지했습니다.

`S = min(캔버스 너비 − 32px, 캔버스 높이 − 48px)`이며, 캔버스 중앙을 원점으로 정규화합니다.

| 조건 | 최종 값 |
| --- | --- |
| 시작점에서 놓는 점까지 직선 이동 거리 | `>= 0.18S` |
| 놓는 점의 중앙으로부터 거리 | `> 0.24S` |
| 최근 바깥 방향 속도 | `>= 1.4S/초` |
| 속도 계산 창 | 정확히 최근 `100ms` |

입력 이벤트의 위치·타임스탬프로 계산합니다. 창 시작점은 표본 사이를 보간하고, 입력 시작 전과 마지막 표본 후에는 정지 표본을 적용합니다. 속도는 최근 변위의 최종 바깥 방향 투영과 실제 중앙 반경 증가량 중 작은 값을 0.1초로 나눕니다. 따라서 접선 방향 원운동이나 과거 빠른 움직임을 그대로 발사 속도로 쓰지 않습니다. 렌더 평가 횟수·FPS는 판정을 바꾸지 않습니다. 세 조건을 모두 만족하는 해제만 한 번 발사하며 경계의 던지는 방향이 금빛으로 밝아집니다. 손을 멈추면 피드백도 약 100ms 이내에 사라집니다.

### 비행·시드 연결과 모션 감소

`hand-flight.js`는 해제 순간 각 물체의 화면 좌표·속도를 복사합니다. 던지는 방향 앞쪽 핀볼부터 0~120ms의 지연으로 추진을 시작합니다. 초기 위치·속도를 보존하는 5차 곡선과 실제 입력 방향의 추진 곡선을 사용해 각 ID의 경기 슬롯까지 이동합니다. 정상 모드의 카메라는 비행 집합을 따라 이동하며 같은 변환을 맵과 핀볼에 적용합니다. 화면 전체 페이드로 교체하거나 맵 입구로 순간 이동하지 않습니다. 마지막 프레임은 실제 경기 카메라의 슬롯 좌표·반지름과 일치시키고, 다음 프레임부터 경기 시간을 진행합니다.

비행 중 화면 크기가 바뀌면 남은 경로에서 공통 카메라 보정을 부드럽게 연결합니다. 반복 변경 시 보정 속도도 이어받으며 ID와 목표 슬롯은 바꾸지 않습니다.

일반 게임의 새 시드 생성 정책을 유지했습니다. 고정 시드·참가자·경기 설정에서 기존 시드 기반 슬롯 순열을 한 번 적용합니다. `commitHandSlots()`는 원래 출발 슬롯의 좌표·속도·앵커를 해당 ID에 연결합니다. 드래그, 대기 시간, 시각적 난수, 비행 시간은 경기 RNG를 소비하지 않습니다. 시각적으로 섞인 순서가 실제 슬롯 소유권을 바꾸지는 않습니다. 각 화면 핀볼이 자신의 고정 슬롯으로 날아갑니다.

모션 감소에서도 물리 셔플과 발사 판정은 같습니다. 비행은 일반 2.8초, 감소 모드 1.2초이며 카메라 이동·궤적 잔상·금빛 번짐을 줄입니다. 설정 변경으로 핀볼 좌표를 재생성하지 않습니다. 셔플 누적 시간은 50ms로 제한해 멈춘 시간을 한 번에 따라잡지 않습니다. 비행 도중의 변경도 기존 경로를 초기화하지 않습니다.

## 실제 브라우저 실행·직접 관찰

Codex 내장 브라우저의 실제 HTML·Canvas·requestAnimationFrame·실제 경기 엔진을 실행했습니다. 1280×720, 390×844, 844×390 각각에서 6·50·200·500개를 검수했습니다. 검수 페이지 [qa.html](qa.html)은 설정 UI로 시작하고 입력 이벤트를 재생하며 실시간 화면과 수치를 기록합니다. 제품의 진입 페이지에서는 로드하지 않습니다.

**입력은 검수 페이지가 만든 합성 PointerEvent입니다.** 검수 ID 999의 포인터 캡처는 검수 페이지에서 우회합니다. 따라서 아래 결과는 실제 브라우저의 렌더·물리·판정·인계 실행이며, OS가 전달한 마우스·실제 휴대폰 터치 및 브라우저 네이티브 캡처의 검증은 아닙니다. 네이티브 드래그를 시도했지만 IAB에서 입력 콜백을 확인하지 못했고, Chrome의 네이티브 드래그 도구는 창 접근 오류로 실행하지 못했습니다. 자동 입력 모듈 검사의 범위와 구분합니다.

12개 조합 모두 집합을 가로지르는 직선(`−0.12S → 0.18S`), 급반전, 원형 경로에서 실제 순서 교환과 충돌을 확인했습니다. 느린 바깥 이동·0.17S의 짧은 빠른 움직임·멈춘 뒤 놓기·경계 흔들림·터치 취소는 셔플에 남았습니다. 빠른 바깥 던지기만 발사했고 중복 해제로 두 번째 발사가 생기지 않았습니다. 셔플→비행 ID가 모두 일치하고, 실제 맵 인계의 최종 화면 위치 오차는 기록상 0px입니다.

직접 화면으로 옅은 경계, 금빛 방향 피드백, 핀볼 출현·섞임·퍼짐, 카메라와 맵 진입을 관찰했습니다. 비행 캡처는 실제 렌더 프레임을 약 88% 시점에 검수용 이미지로 고정한 것이며, 뒤의 실제 경기는 계속 진행합니다. 캡처 옆 현재 통계와 고정 화면의 시점이 다를 수 있습니다.

## 남은 문제·검증 한계

- 실제 iPhone/iOS Safari, Android Chrome·인앱 브라우저와 휴대폰 성능은 확인하지 않았습니다. 네이티브 포인터 캡처, 실제 다중 터치·브라우저 제스처 간섭은 기기 검수가 필요합니다. 합성 입력·모의 DOM 검사 결과로 실기기 통과를 주장하지 않습니다.
- 브라우저 콘솔에 `MutationObserver.observe`의 Node 타입 오류 6개가 기록됐습니다. 프로젝트 코드에는 MutationObserver 사용이 없어 검수 도구 주입 관련으로 추정하지만, 원인은 확정하지 못했습니다. 실행 흐름·측정 검사에서는 실패가 없었습니다. [오류 원본](browser-console.json). 콘솔 무오류로 보고하지 않습니다.
- 아주 약한 한쪽 방향의 짧은 드래그에서는 충돌해도 앞뒤 순서가 유지될 수 있습니다. 강제 무작위 교환을 넣지 않았습니다. 집합을 가로지르는 대표 직선·급반전·원형 경로는 12개 화면·인원 조합에서 위치 교환을 확인했습니다.
- 중앙 셔플은 실제 2D 원형 충돌이며, 비행은 해제 상태를 잇는 Canvas 2D 경로·카메라 연출입니다. 비행 중 별도의 강체 충돌, 유리의 굴절, 입체 깊이·PBR 광학은 구현 범위에 포함하지 않았습니다.
- 500개 세로 화면에서는 반경이 약 2px로 작아 개별 이름을 표시하지 않습니다. ID·색상·슬롯은 유지되며, 작은 인원에서 이름표가 가까이 배치되는 경우는 있습니다. 실제 청감 검증은 하지 않았습니다.
