# 실제 셔플 위치를 경기 출발에 반영

검증일: 2026-10-11. 프로젝트 `/Users/proudchris/Desktop/moonbangoo_PinBall`, 미리보기 http://127.0.0.1:8778/ . 푸시·배포 없음.

## 원인

기존 `commitHandSlots`는 셔플 공의 좌표를 읽지 않고, 시드로 정한 lane 순서에 최초 경기 슬롯을 다시 배정했습니다. 셔플은 실제 충돌과 위치 교환을 했지만 경기 출발에는 영향이 없었습니다. 브라우저 설정에는 수동 QA 시드 `EDGE-QA-50`도 저장돼 있었습니다. 따라서 같은 참가자/설정/시드에서 동일한 경기 출발과 결과가 반복됐습니다. 참가자는 귤4개·수박2개·키위2개로, 과일별 동일한 개수가 아닙니다.

## 수정

- `hand-start.js`에서 발사 순간의 각 ID별 실제 x/y/vx/vy를 복사하고, 맵의 장애물 없는 출발 사각형에 좌표 변환합니다. 공의 상대 위치와 무리의 이동을 반영하며 시드 슬롯에 다시 배정하지 않습니다.
- 작은 인원은 원래 반지름 비율에 맞춘 같은 축척을 사용합니다. 구역을 넘는 크기는 축별 축척과 전체 이동만 제한합니다. 겹침은 기존 공간 해시 충돌 제약으로 보정합니다.
- 고밀도에서 60회 보정 후에도 1% 이상의 겹침이 남으면 안전한 육각 배치를 바탕으로 실제 셔플 위치에 가까운 곳을 ID별로 찾아 배치하고 충돌 없는 경로로 원래 투영 위치까지 당깁니다. 소유권은 실제 셔플 위치에 의해 결정됩니다. 500개·큰 반지름에서는 공 간 위치가 정확한 등비 변환으로 유지되지는 않습니다.
- 실제 출발 속도는 각 공의 제스처 물리 속도를 좌표 축척에 맞춰 전달합니다. 경기 진입의 과도한 에너지를 막기 위해 크기만 120 world units/s로 제한하며 방향은 유지합니다.
- 동일한 공 ID가 셔플의 마지막 상태 → 비행 시작 → 새 실제 출발 위치 → 경기까지 이어집니다. 두 번 적용하지 않으며, 경기 RNG는 소비하지 않습니다. 경기의 시간은 비행 동안 0입니다.
- `physics.js`, `maps.js`, `race-standing.js`, `renderer.js`, `ui.js`는 수정하지 않았습니다. 경기 물리·막힘 방지·규칙·순위·도착 시간·결과 화면은 유지했습니다.

## 새 재현 정책

사용자가 요구한 실제 셔플 반영은 이전의 “같은 시드면 어떤 드래그여도 같은 결과” 정책을 대체합니다. 일반 게임은 빈 시드에서 매번 새 시드를 사용합니다. 고정 시드는 초기 준비와 경기 RNG를 재현하지만 **최종 결과 재현에는 같은 시드·참가자·설정과 같은 발사 스냅샷이 필요**합니다. 프레임 묶음/모션 감소 설정 자체가 매핑에 들어가지는 않습니다. 실제 셔플 좌표가 달라졌다면 같은 제스처 의도나 같은 시드만으로 결과가 같다고 보장하지 않습니다.

런타임 `physics.handStart`에 version/seed/source/starts/transform/correctionPasses/denseFit를 기록합니다. QA JSON에 이를 저장했습니다. 이번 범위에는 스냅샷을 다시 불러오는 사용자 UI를 추가하지 않았습니다.
