# 초기 설정의 특정 귤 선두 표시 수정 — 2026-10-08

## 원인

사용자의 저장된 초기 설정 `귤*4,수박*2,키위*2` /속도1 /시드 공란으로 확인했습니다. 작은 그룹의 출발 슬롯은 가로 위치가 랜덤이어도 모두 같은 높이로 시작합니다. 처음 자유 낙하 구간에는 실제 진행 높이도 같습니다. 기존 `getRanking()`의 동률 정렬은 `colorIndex` 즉 참가자 입력 순서를 사용했고, 화면은 항상 배열 첫 공을 단독 선두로 강조했습니다. 그 결과 첫 참가자인 귤 ID1이 출발 직후 매번 선두로 고정된 것처럼 보였습니다. 고정된 왼쪽 슬롯 소유권이나 일반 게임 시드 재사용 문제는 아니었습니다.

Node에서 시드A/B/C/D를 바꿔도 0~0.5초 높이 차이가0인데 ID1이 순위 배열 첫 공임을 재현했습니다. 장애물 충돌 후 실제 선두는 서로 달라졌습니다.

## 수정

`race-standing.js`는 표시용 공동 순위와 단독 선두만 계산합니다. 미완주 공들의 높이 차이가 수치 오차 범위1e−7 이하이면 공동 순위이며, 공동1위에서는 단독 선두가 없습니다. 실제 높이 차이가 생기면 가장 앞선 공에 기존 강조가 붙습니다. 라이브 순위판은 공동 순위(01,01,… 또는01,02,02,04)를 표시하며, 동률 항목의 화면 순서는 기존 안정된 입력 순서를 유지합니다. 미니맵도 동률일 때 특정 공만 강조하지 않습니다. 선두 교체 알림도 공동 선두에서 특정 참가자를 임의로 고르지 않습니다.

경기 엔진 `physics.js`, 실제 정렬/완주 동률 정책, 시드·RNG·출발 슬롯·도착 시간·결과 순위·맵·카메라·비행은 변경하지 않았습니다. 완주한 공의 순위는 동률 표시 대상에서 제외하므로 결과 순서를 유지합니다. 변경 스크립트 캐시 버전을 갱신했습니다.
