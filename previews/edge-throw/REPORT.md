## 최종 물리와 발사 기준

`S = min(화면 폭 − 32px, 화면 높이 − 48px)`입니다. 중앙 집합 반지름은 `0.30S` (지름 `0.60S`), 핀볼 반지름은 `min(0.044, 0.18/√인원수) × S`입니다. 6·50·200·500개의 반지름은 각각 약 `0.044S`, `0.02546S`, `0.01273S`, `0.00805S`이며 렌더링과 셔플 충돌이 같은 반지름을 사용합니다.

손 영향 반지름은 `0.26S`, 이동하는 손의 부드러운 압력 코어는 `0.045S`입니다. 실제 입력 구간과 각 공 사이의 거리에 따라 `(1−거리/영향반지름)²` 가중치로 개별 속도 충격을 전달합니다. 실제 충격 크기 `>1e−7`을 기록해야 접촉 조건을 충족합니다. 따라서 빈 공간만 이동하면 접촉했다고 판단하지 않습니다. 속도는 이벤트 위치·시간으로 계산하며 물리 입력 속도를 최대 `2.8S/초`로 제한합니다. 이 충격은 렌더 프레임 전에 놓아도 접촉 기록을 남깁니다. 모든 공의 좌표를 직접 옮기는 코드는 없습니다.

120Hz 고정 물리 단계, 최대 12개 적응 서브스텝과 공간 해시 충돌을 유지합니다. 중력 계수 `0.008`, 복귀 계수 드래그 중 `0.06` / 해제 후 `0.36`, 집합 바깥 추가 복귀 계수 `2.4`, 감쇠 계수 드래그 중 `1.65` / 해제 후 `1.9`를 사용합니다. 정지한 손의 입력 힘은 시간에 따라 줄어들며, 공은 현재 위치·속도에서 관성 후 감속합니다. 복귀할 때 위치나 속도를 초기화하지 않습니다. ID별 파동이나 반복 진동 힘은 없습니다.

발사 상수는 `js/throw-gate.js`의 `THROW_THRESHOLDS`와 공유 `EDGE_GEOMETRY`가 관리합니다.

정상 놓기와 준비 표시가 같은 게이트 결과를 사용합니다. 짧은 움직임·빈 가장자리 클릭·접촉 없는 이동은 금빛으로 표시하거나 발사하지 않습니다. 충분히 안쪽으로 돌아오면 즉시 준비가 해제되고 밝기만 부드럽게 감소합니다. 취소·포커스 상실·회전·다중 터치는 항상 발사하지 않습니다. 두 번째 접촉은 제스처를 취소하고 모두 놓을 때까지 차단합니다. 중복 놓기는 이미 종료된 제스처를 다시 발사하지 않습니다.

기존 캔버스 `grab` / `grabbing` 커서와 셔플 화면에 한정된 `touch-action:none`을 유지합니다. 마우스가 실제 캔버스에 도달하도록 기존 CSS 내용 해시 URL `hand-e6756af51da9`를 보존했고, 이번에 바뀐 5개 JS의 캐시 버전을 `edge-20261007`로 갱신했습니다. 설정의 스크롤과 `touch-action:auto`는 유지합니다.

## 비행·시드·모션 감소

놓기 순간의 각 공 위치·속도를 그대로 사용합니다. 기존 비행 곡선의 시작 위치·속도 연속성, 앞쪽 공부터 0~120ms 지연 추진, 실제 핀볼을 따르는 카메라, 각 ID의 시드로 정해진 실제 경기 슬롯 종점을 유지합니다. 정지 놓기에서도 기본 추진력 `0.8S`, 빠른 입력에는 최대 `0.28S`를 추가합니다. 모션 감소의 추진력은 `0.12S`이며 기존 짧은 진입·잔상 억제·광택 번짐 억제를 유지합니다. 발사 판정은 모션 설정과 무관합니다.

시각적 셔플에는 별도 `seed|hand-visual-only` 스트림을 사용합니다. 제스처는 눈에 보이는 셔플·비행의 출발 상태에 영향을 주며, 경기 RNG·슬롯 소유권·경기 초기 속도에는 영향을 주지 않습니다. 따라서 시각적 위치 교환이 실제 출발 슬롯을 다시 추첨한다는 의미는 아닙니다. 일반 게임의 새로운 시드 생성, 같은 고정 시드·참가자·경기 설정의 재현성은 유지합니다.

일반/모션 감소 500개 실제 브라우저 경기에서 전체 슬롯 배열과 500개 전체 완주 ID·순위·물리 도착 시간이 정확히 일치했습니다. 변경 중인 모션 설정은 현재 좌표·속도와 elapsed·accumulator를 즉시 비교해 모두 보존됨을 확인했습니다. 기존 자동 검사도 대기·제스처·렌더 프레임 묶음이 다른 전체 경기 재현성을 검사합니다.

재검수용 [qa.html](qa.html)은 실제 제품을 iframe으로 열고 버튼으로 테스트용 참가자·고정 시드·3배 경기 속도·음소거를 설정합니다. 실행 시 브라우저 저장 설정이 변경되므로 검수 후 원래 설정을 되돌려야 합니다. 합성 포인터 ID 999만 테스트 페이지에서 캡처 API를 보완하고, 실제 마우스 캡처는 그대로 사용합니다. 제품의 입력·게이트·물리 구현을 우회하지 않습니다. 이 페이지는 제품 사용 흐름에 추가되지 않았습니다.

남은 한계:

- 휴대폰 실기기 터치·저사양 성능, iOS Safari·Android Chrome·인앱 브라우저는 이번에 사용하지 않았습니다. 모바일 화면 크기 검증과 실제 휴대폰 검증은 별개입니다.
- IAB 로그에 문서 로드/재로드마다 `MutationObserver.observe`의 Node 인자 오류가 발생했고 총 3개를 보존했습니다 ([원시 로그](browser-console.json)). 제품 소스에 해당 observer 호출은 없고 검수 도구 주입과 관련될 가능성이 있지만 원인은 확정하지 않았습니다. 실행 중 물리·입력 실패는 관찰하지 않았습니다.
- 500개 세로에서는 셔플 반지름 약 2.88px여서 개별 색상/위치 이동은 보이지만 이름과 세부 반사를 읽기 어렵습니다. 기존 2D Canvas 비행·유리관 이미지의 깊이 표현 한계는 유지합니다. 공이 이미 넓게 퍼져 있으면 손 영향 범위 밖의 공은 직접 따라오지 않습니다.
- 금빛은 준비를 충족한 가장자리 방향에만 표시합니다. 의도적으로 공을 중앙으로 다시 충분히 밀어야 준비가 해제됩니다. 별도의 발사 버튼·새 대포 에셋은 추가하지 않았습니다.

검수 후 원래 참가자 `귤*4,수박*2,키위*2`, 반지름11·중력620·반발력0.72·속도1·품질high·볼륨0.35·효과음켜짐·스킬꺼짐·모션감소꺼짐·빈 시드와 대기 화면을 복원했습니다. 뷰포트 임시 설정을 해제하고 실제 제품 탭을 남겼습니다.
